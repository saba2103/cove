# Cove v2 — the prompt series

One prompt per task, in order. Each ends in a check Antigravity must run and pass;
none of them are "done" on the agent's say-so.

Paste them one at a time. Don't batch — the gates are what keep the series honest,
and a batched prompt skips them.

---

## Phase 0 — safety. No UI work.

### Prompt 0.1 — land the bundle and prove the generator

> Unzip `cove-v2-bundle` into the repo root, keeping paths. Put the four
> `PlusJakartaSans-*.ttf` files and `OFL.txt` in `assets/fonts/` and register the
> family in `pubspec.yaml` under the existing `fonts:` block, weights 400/500/600/700.
> Leave the GeneralSans entry exactly as it is.
>
> Then **run `dart run tool/gen_tokens.dart` and `git diff lib/core/theme/cove_tokens.dart`.**
> The diff must be empty. The committed file was generated by a faithful port of that
> script, so if the diff is non-empty the generator is wrong and the committed file is
> right: fix `tool/gen_tokens.dart` until it reproduces the committed file byte for
> byte, and do not edit `cove_tokens.dart` by hand.
>
> Then run `python3 tool/check_contrast.py`, `dart run tool/style_gate.dart` and
> `flutter analyze`. Report all four results. Do not change any screen.

### Prompt 0.2 — capture the schema before anything moves

> Run `dart run drift_dev schema dump lib/sync/db/app_database.dart drift_schemas/`
> and commit the result. This captures schema v11, the shape the live data is in —
> once we migrate past v11 it can never be generated again.
>
> Then add a migration test that builds a v11 database from that snapshot, inserts one
> row into every table, migrates to the current version, and asserts every row survives
> with its values intact. It must fail if a column is dropped or renamed.

### Prompt 0.3 — baseline goldens of the app as it is today

> Add `test/golden/golden_harness.dart` (in the bundle) to the test suite. Wire
> `coveThemeFor(Brightness)` at the bottom of it to the existing `cove_theme.dart`
> factories — for now, the current theme, not the new tokens.
>
> Write one golden test per screen for all thirteen in the prototype's scope, using
> `goldenMatrix`. Generate the goldens with `flutter test --update-goldens` and commit
> them. These are the "before" — do not change a single widget while doing this. If a
> screen can't be pumped without a database, stub the providers through the `overrides`
> parameter rather than reaching for a real one.

### Prompt 0.4 — make the Definition of Done mechanical

> Replace steps 1 and 2 of the Definition of Done in `AGENTS.md` and
> `.agent/rules/definition_of_done.md` with: "Run `tool/check.sh`. It must exit 0."
> Keep the changelog and product-decision steps as they are.

## Phase 1 — tokens become the theme

### Prompt 1.1 — theme reads the tokens

> Make `cove_theme.dart` put `CoveTokens.dark` and `CoveTokens.light` into
> `ThemeData.extensions`, alongside the existing `CoveColors` — both coexist until
> the style allow-list is empty. Map `ColorScheme` and `TextTheme` from `CoveTokens`
> and `CoveType` so Material defaults stop fighting us.
>
> Point `coveThemeFor()` in the golden harness at the new factories. Goldens for
> unconverted screens may shift slightly where Material defaults change — regenerate
> and eyeball the diffs before committing; anything that is not explained by a token
> value is a bug, not a baseline.
>
> `tool/check.sh` must exit 0.

### Prompt 1.2 — the version bump

> Set `pubspec.yaml` to `version: 2.0.0-alpha.1+1`. Update `kCoveCurrentAppVersion`
> to `'2.0.0-alpha.1'` and add a `kChangelogItems` entry for **v2.0-alpha.1 — The
> Design System**. Update `about_cove_screen.dart` to display `v2.0-alpha.1 (1)`.
> Add the milestone row to `product/versioning_and_git_strategy.md` §2.
> `dart run tool/check_version.dart` must pass.

## Phase 2 — the primitives, before any screen

One prompt each, in this order. Each: build the widget from `CoveTokens` / `CoveType` /
`CoveSpace` / `CoveRadius` only, add a golden via `goldenMatrix`, and leave the screens
untouched.

1. `CoveStatusBar` — 11.5sp equivalent at device scale, one bar, four dots at 50%
2. `CovePageHeader` — 28sp Bodoni title on a 36dp line box, one 40dp round action, 48dp hit
3. `CoveSectionLabel` — the two caps variants, `capsPage` and `capsCard`
4. `CoveRow` — 52dp height, 12dp hit plate with its equal negative margin
5. `CoveMetricCard` — 20dp radius
6. `CoveRoundButton` — 40dp drawn, 48dp hit, gold fill or bordered ghost
7. `CoveAvatar` — 24/28/32/64, `person.a`/`person.b` fills, `person.both` as an **unfilled ring**
8. `CoveSheet` — 32dp top, 40dp bottom where it meets the edge
9. `CoveToast` — below the status bar and any header, never over them; must not auto-dismiss before an assistive-tech user reaches Undo
10. `CoveFloatingBar` — Home · Money · Tasks · Calendar, centre +, the detaching category row

## Phase 3 — screens, one prompt each

Today · Calendar · Expenses · Commitments · EMIs · The year · Routines · Activity ·
Our home · Settings · Add · detail sheets · notification copy and batching.

Each prompt: convert to the primitives, delete the file's line from
`tool/style_allowlist.txt`, regenerate its goldens, and pass `tool/check.sh`.

## Phase 4 — the new things

First-run empty states · the Android app widget (`home_widget` + a WorkManager refresh;
Android only, no iOS project exists) · the undesigned screens taking tokens only, same
layout, until their budgets reach 0.

## Phase 5 — accessibility

Text at 200% · orientation · text alternatives for the drawn pages and charts · slip
state as semantics · a non-drag way to set a time · the custom keypad with VoiceOver,
Voice Control, Switch Control and a hardware keyboard · Reduce Motion through
`CoveMotion.q()` / `.s()`.
